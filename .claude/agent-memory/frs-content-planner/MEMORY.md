# frs-content-planner — persistent learnings

Append-only patterns observed across runs. Not per-week notes.

## Patterns

- While the `posts` tab is empty (no engagement data yet), default to maximum pillar variety: rotate across all 6 pillars before repeating any single pillar. W17 used (ai-agent-thesis, pm-lessons, workflow-first); W18 used the other three (contrarian-takes, founders-dilemma, behind-the-process). Keep this 2-week full-rotation pattern until real engagement signals are available.
- After completing a 2-week full 6-pillar rotation with no engagement data, restart the cycle by mirroring the prior W17-style mix with fresh, non-repeating angles. W19 mirrored W17's pillar mix (ai-agent-thesis, pm-lessons, workflow-first) with all-new angles. The next "even" week (W20-style) should mirror W18's mix (contrarian-takes, founders-dilemma, behind-the-process) with fresh angles. Continue this 2-week alternation until engagement data unlocks signal-weighted planning.
- Linear MCP is not always configured in the run environment. When unavailable, write the plan + leave `post_ideas.linear_issue` empty, and include a "Linear issues to create (manual)" section in the plan file with full title/description/due-date for each issue so the human can paste them in.
- The `content` label was reported as missing in the RyanIrwin Linear workspace in W17. Until confirmed otherwise, instruct the human to create issues without the label or create the label once.
- `scripts/sheet.py` has historically needed `SSL_CERT_FILE` patching for `httplib2` in sandboxed envs (per W17 notes). Additionally, sandboxed envs may be missing `cffi` (`ModuleNotFoundError: _cffi_backend`) — a `pip install cffi` resolves it. If a sheet read/write fails, check both.
- Always check `post_ideas` for any rows already scheduled for the target week before appending. Partial prior runs may have written rows without creating Linear issues; promote those rather than duplicating.
- 60-day angle-repeat rule: cross-check planned angles against the full `post_ideas` tab (not just `posts`), since `posts` may stay empty for a long time while `post_ideas` accumulates the actual rotation history.
- Idempotent-rerun case: if invoked for a week whose plan file already exists AND `post_ideas` already has the right number of `status=scheduled` rows for the target week's dates, do NOT add new rows or rewrite the plan file. Re-attempt Linear issue creation only if MCP is now available; otherwise return the existing plan summary with LINEAR_SKIPPED. Adding more rows in this case would violate the `count` cap and create duplicate ideas.
- Idempotent sub-case "planned but not pushed" (seen 2026-05-25 for W23): a prior run can leave the plan committed locally (HEAD = "plan: W23 content calendar", 1 commit ahead of origin/main) but never pushed, so the Draft Post routine can't read it from the remote. When re-invoked for that week, the correct delivery is just `git push origin HEAD:main` (with backoff) — NOT re-planning. Verify the local commit actually contains the plan file via `git ls-tree -r <sha> | grep W<NN>`; a transient `git status` can momentarily show the plan file as `??` untracked even when it is in HEAD, so trust `git diff HEAD -- <file>` (empty output = clean/committed) over a single status read.
- "Coming week" disambiguation: when today is itself a Monday, "this coming week" = the week starting the NEXT Monday (today+7), not today's partial week. On 2026-05-25 (Mon, W22), "coming week" resolved to W23 (2026-06-01), which was already planned, so the run became a deliver/push-only re-run rather than a new plan.
- Branch caveat: the spec says "push to main", but the agent often runs on a feature branch (e.g. `claude/<id>`) where unrelated work is also staged. Do NOT sweep unrelated commits onto main. If the plan commit is already on the current branch and the branch is the one the human merges from, treat that as "delivered" — don't force-push or cherry-pick across branches without the human's call. SAFE push pattern when the branch is exactly origin/main + the single plan commit (`git rev-list --left-right --count origin/main...HEAD` shows `0 1`): `git push origin HEAD:main` cleanly fast-forwards main without switching branches.
- Rotation cycle is self-consistent in the Sheet even when plan files are missing. As of W21 the `post_ideas` history showed: W17/W19/W21 = odd mix (ai-agent-thesis, pm-lessons, workflow-first); W18/W20 = even mix (contrarian-takes, founders-dilemma, behind-the-process). W22 was skipped (no rows). W23 (2026-06-01) correctly used the even mix with fresh angles (contrarian "AI hire vs plan", founders "cost of bad first move", behind-the-process "framework for evaluating AI feature bets"). Trust the Sheet's `post_ideas` as the rotation source of truth, not the plan-files directory, which can be incomplete.
- cffi fix that works OFFLINE: `pip install cffi` FAILS when the sandbox has no network (ReadTimeoutError to pythonhosted). Instead, point PYTHONPATH at the prebuilt cffi 2.0.0 in the uv cache: `export PYTHONPATH="/root/.cache/uv/archive-v0/zSE9vzNXNv-OAMWMUNCMZ:$PYTHONPATH"` (contains both `cffi/` and `_cffi_backend.cpython-311-*.so`, matching the python3.11 sheet.py runs under). If that exact hash dir is gone, find one with `find / -path '*/cffi/__init__.py' 2>/dev/null` and confirm a sibling `_cffi_backend.cpython-311*.so` exists. Prepend it to PYTHONPATH on every sheet.py invocation in this session.
