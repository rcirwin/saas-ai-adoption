## Heuristics Confirmed

- **A backgrounded `nohup ... &` launch reports task-complete immediately; poll the output file, not the task notification (2026-07-30)**: the 30-write sheet loop was launched as `nohup python3 write_sheets.py > sheets.out 2>&1 &` inside a `run_in_background` Bash call. The launching shell exits in under a second, so the harness fired a "background command completed, exit code 0" notification while only 5 of 30 writes had landed. The writer was still running fine (`ps` confirmed it), but acting on that notification would have meant committing a half-written run. **How to apply**: after launching a paced sheet-write loop, never treat the task-completion notification as done. Wait on the sentinel instead (`until grep -q "^TOTAL" sheets.out; do sleep 3; done`) and confirm `TOTAL OK=<2N> FAILS=0` before writing the summary or committing.

- **The departed regex catches "new CEO" phrasing, which is softer than confirmed departure (2026-07-30)**: running the disqualifier as a pre-filter over `research_cache.pain_signals` + `fit_notes` removed 33 prospects, 4 of them on cache language alone. Two of those four are genuinely stale (`employeeconnect`, `snap-surveys` both name a successor). The other two are not: `prezly` says "new CEO Jesse Chan" while co-founder Gijs Nelissen is still the reachable contact (the 2026-07-17 run drafted him on purpose), and `deconetwork` reads only "recent leadership change". **How to apply**: keep the pre-filter, it is cheap and safe, but record which prospects were removed by cache language versus by a `skipped-founder-departed` log row. The cache-language-only set is recoverable with a name check rather than full re-research, which matters when the eligible pool thins out. Do not silently collapse the two categories in the run summary.
