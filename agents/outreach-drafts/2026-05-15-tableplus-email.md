Subject: TablePlus + MCP or fade

Henry,

Cursor and Claude Code write queries inside the IDE now. That's the actual pressure on TablePlus, not DBeaver or DataGrip.

The reflex move is "ship an AI query assistant in TablePlus to keep up." That keeps TablePlus in a parity race the IDE AIs already won, because they have the developer's context, file tree, and schema in one place. The harder, more interesting framing is that TablePlus becomes the database execution layer for those agents. An MCP server (or equivalent) that Cursor and Claude Code invoke for database operations they can't do natively, like complex transactional ops, multi-database joins, or schema migrations with the safety GUI handles well.

That positions TablePlus as the agent-ready database surface, not as a competing AI query writer. Different game, more defensible.

The solo bootstrapped founders I've been comparing notes with at your stage keep landing on this exact framing for dev tools.
