### Process learnings
1. **Bash shell-injection on `$` gotcha** (per memory): every append must single-quote `notes` if it contains `$`. Hit zero times this run because I avoided embedded `$` in notes.
2. **Multi-clause `--where` works for `sheet.py update`** — confirmed `--where 'id=X' 'created_at=Y' 'source=Z'` AND's all filters. Use this for any disambiguation.
3. **Sheet API rate-limit recovery**: 60 reads/min/user/project gets saturated when 10 sourcer agents run concurrently. Use `until X; do sleep 15; done` patterns to poll. Avoid spurious reads in tight loops.
4. **Catastrophic-update incident** (lesson logged separately): single-clause `update --where 'id=referralcandy' --set 'id=DELETED-...'` nuked 14 rows because the original `referralcandy` was the only constraint, and the same id existed across 14 unique rows due to a prior bulk-rename. Restoration took 60+ minutes. Going forward: always pass at least one disambiguator (`created_at` or `source` or distinct `notes` substring) when DELETE-tagging.
5. **In-flight duplicate detection during concurrent runs**: ~10 sourcer agents running concurrently → static dedup at run-start undercounts. Re-check dedup via grep after every batch of 5 appends. Hit duplicates this run with rivo, repurpose-io, vendor, cratejoy, bookwhen, pabbly, reditus, affilimate, booqable — all from sibling agents adding to the same sheet during my run.
